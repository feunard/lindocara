# Authored NPC movement

Normal map events use the XP-style movement fields already stored on each active page. The server
remains authoritative: `npc-movement-system.ts` chooses one collision-safe target cell at the shared
cadence from `event-movement.ts`, then event deltas send that target to every room client.

The renderer does not predict NPC decisions. It only presents the last authoritative step:

- tween from the currently displayed position to the new target cell;
- use the page's speed and frequency to match the server cadence;
- switch an idle character sheet to its catalogued Tiny Swords run sheet while moving;
- preserve vertical facing and flip horizontally unless `optDirFix` is set;
- Y-sort character events with players and keep `optOnTop` events above actors;
- move quest markers with the displayed NPC position.

Idle-to-run relationships are generated by the Tiny Swords catalogue. Each character `Idle` entry
must resolve to the official sibling `Run` sheet, whose frames are sliced from exact sheet geometry.
Non-character event graphics still tween between cells but keep their authored appearance.

Movement state is room-owned and deterministic. Clients never send NPC positions, route steps,
animation frames or movement outcomes.
