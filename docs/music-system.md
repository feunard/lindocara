# Lindocara music system

Lindocara has one local generation lane and one independent runtime playback layer. Music is
generated by the existing `studio.py` entry point with ACE-Step 1.5, recorded in a reproducible
registry, compiled into the engine catalogue, and then selected by the browser from authored map
audio data. No model or Python code ships to the game client.

## Sources of truth

- `studio/musics/lindocara-music.json` is **Lindocara Music DNA**: shared instruments, emotions,
  exclusions, the five-note main motif, generator capabilities, ten profiles and transition times.
- `studio/musics/generations.json` records every promoted take: profile, biome tags, mood,
  intensity, BPM, duration, loop flag, exact seed, effective prompt, generator, parameters, public
  URL and creation date. Parameters include the diffusion model, language model, numerical backend
  and sample rate, so regeneration does not silently follow a later studio default.
- `packages/engine/src/music-catalog.generated.ts` is generated by `yarn music:catalog`. Never
  edit it by hand. `yarn music:check` rejects drift or a registry entry whose audio file is
  missing.
- `packages/engine/src/audio-catalog.ts` owns the persisted map/adventure audio contract and the
  data-driven state priority.
- `packages/client/src/game/dynamic-music.ts` owns two-deck playback, crossfades and playlist seams.
  It knows nothing about generation prompts.

The motif is `D4–A4–C5–G4–A4`: tonic, fifth, minor seventh, fourth, fifth. ACE-Step does not offer
note-exact MIDI conditioning through the integrated runner, so the notes and contour are injected
into every profile prompt. The schema also keeps a nullable `referenceAudio`; a future approved
motif render can be supplied through `--reference-audio` without redesigning the catalogue.

## Generator and limits

The existing music lane uses local **ACE-Step 1.5** (`acestep-v15-turbo`, 3.5B diffusion model,
`acestep-5Hz-lm-1.7B` language model), at 48 kHz. The code is MIT and the weights are Apache-2.0.
The integrated API accepts 10–600 seconds, 30–300 BPM, deterministic seeds, instrumental/vocal
mode and an optional reference audio file. The turbo model uses eight diffusion steps by default.

Important limits:

- captions are limited to 512 characters; the prompt composer keeps DNA, profile instruments,
  motif and technical exclusions inside that limit;
- the model follows instrumentation and tempo more reliably than detailed structure;
- a seed is repeatable on the same model/backend, but a model revision or another numerical
  backend may introduce small differences;
- generated tracks usually contain an introduction and ending and are not guaranteed sample-clean
  loops;
- output is a normalized mix, not a separately mastered soundtrack.

The runner explicitly sets `GenerationConfig(use_random_seed=False, seeds=[seed])`. This matters:
ACE-Step defaults to random seeds at the config level, which otherwise overrides the seed stored in
`GenerationParams`.

## CLI

On Windows use `python`; on macOS/Linux use `python3`.

```bash
python studio/studio.py music --list-profiles
python studio/studio.py music --profile exploration --duration 140 --variants 3 --seed 18201
python studio/studio.py music --profile snow --context "an abandoned pass at dawn" --seed 32001
python studio/studio.py music --list-generations
python studio/studio.py music --show exploration-01
python studio/studio.py music --play exploration-01
python studio/studio.py music --regenerate exploration-01
python studio/studio.py music --delete exploration-01 --yes
```

Profile generation automatically performs the conceptual operation:

```ts
generateMusic({ profile: "snow", duration: 140, variations: 2, loopable: false });
```

It composes `Music DNA + motif + profile + --context + technical constraints`, assigns stable IDs,
writes the public files, appends complete metadata and rebuilds the runtime catalogue. `--dry-run`
prints the exact ACE-Step call without creating a file or registry entry. Free-form music remains
available with `--prompt`; unless `--no-theme` is explicit it also receives Music DNA and the main
motif.

`--regenerate` reuses the recorded effective prompt, seed, BPM, duration, step count, format,
reference, diffusion/language models and language-model backend. `--delete --yes` validates that
the target is under the public music directory, moves
the audio into ignored `studio/examples/_deleted-music/`, removes the registry row and rebuilds the
catalogue.

The initial identity prototype uses three exploration seeds (`18201`–`18203`), two snow seeds
(`32001`–`32002`) and two forest seeds (`44001`–`44002`), all at 140 seconds. Later takes should use
new IDs rather than silently replacing those references.

## Files and naming

Promoted music lives in:

```text
packages/client/public/assets/lindocara/audio/music/
```

IDs use kebab case and two-digit variants (`exploration-01`). Files use snake case
(`exploration_01.mp3`). MP3 is the default at 48 kHz / 192 kb/s. Scratch and rejected local takes
belong under the git-ignored `studio/examples/`, never in the public catalogue.

## Adding or changing a profile

Add one object to `profiles` in `studio/musics/lindocara-music.json`. Keep a stable kebab-case ID,
set biome/mood tags, instruments, BPM, intensity, duration, loop capability, destination crossfade
and fallback track IDs, then run:

```bash
yarn music:catalog
yarn music:check
```

The profile ID becomes a strict TypeScript union used by the editor, persistence parser and
runtime. A profile with generated takes plays those variants; until then it uses its explicit
fallback tracks. This lets the ten situations work now without generating the entire OST during
the seven-track identity prototype.

## Authoring maps and adventures

The adventure settings define defaults inherited by every member map. **Sons de la carte** can
override or disable each of these slots independently:

- exploration/biome;
- night;
- great discovery/panorama;
- danger;
- combat;
- boss/major event;
- environmental ambience.

The two direct track fields remain visible as compatibility fallbacks for historical content.
Dynamic profiles take precedence. Existing database columns already store audio as JSON, so no
schema migration is required. Old direct-track payloads are preserved; old adventures without an
authored choice gain the new profile defaults.

Choose `forest` or `snow` as a map's exploration profile to bind a biome today. Lindocara does not
yet have an authoritative generic biome or weather field, so the editor selection is deliberately
explicit rather than inferred unreliably from terrain. When those systems exist, add their state to
the centralized selector instead of scattering conditionals through the client.

## Runtime selection and transitions

The centralized priority is:

```text
boss > confirmed combat > nearby danger > discovery > night > exploration
```

- danger comes from a living server-authored monster threat;
- boss requires a threatening monster whose authoritative rank is `boss`;
- combat starts only from confirmed `combat.hit` / `combat.hurt` events and is held briefly;
- night uses the existing map-stable 24-minute day cycle;
- `discoveryPulse()` is the typed cue for a narrative/location system; it is not guessed from every
  map entrance.

Each destination profile carries its transition time: exploration/night are slow, danger is
progressive, combat and boss are fast. The player keeps at most two HTML audio decks. It preserves
the exploration position when possible, never stacks a third incompatible track, and crossfades
to the next variant near the end of non-loopable music. Truly loopable future tracks can set
`loopable: true` and use native looping instead.

Ambience and short sound effects retain their existing systems: one environmental HTMLAudio loop,
Web Audio buffer caching for effects, persisted volume/mute settings, and browser-gesture unlock.
