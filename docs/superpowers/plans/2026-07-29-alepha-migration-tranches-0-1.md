# Alepha Migration — Tranches 0-1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vendor Alepha into the repo (tranche 0), then stand up the pure-Alepha server — ORM entities, realm auth, and every `/api/*` route as `$action` — alongside the untouched legacy stack (tranche 1).

**Architecture:** Alepha is vendored at `.vendor/alepha` and consumed through npm workspaces. The new server lives in `packages/server/src/api/` (entities, providers, controllers) and is assembled by a new server entry `apps/main/src/main.ts`; the legacy Worker stack keeps running via `dev:legacy` and is not modified. Fresh database (SQLite in dev, D1 later) — zero data migration. Recon verified: the legacy `/api/ws` upgrade CANNOT be co-hosted inside Alepha's generated Cloudflare worker (closed `wsPaths` list from `$websocket` primitives, no raw `Response` handler), so tranche 1 runs the two stacks in parallel and the client cutover happens in the realtime tranche.

**Tech Stack:** Alepha 0.24.0 (vendored from `main`), zod (Alepha's re-export), Drizzle (embedded in Alepha's ORM), Vitest (node environment for new tests), npm workspaces.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-29-alepha-migration-design.md`. Read it before starting.
- `packages/engine` is untouched — any task needing a change there is a plan bug; stop and report.
- Legacy server code (`packages/server/src/*.ts` outside `src/api/`) is not modified in these tranches, except the two explicitly listed edits (apps/main script rename, index.html entry path).
- Machine error codes are preserved verbatim (`username_taken`, `map_conflict`, `hero_cap`, …) via Alepha's `HttpError` `error` field — the legacy client already reads `{error: "<code>"}` so the shape stays compatible.
- New auth constraint accepted by the spec: usernames become 3-16 chars (Alepha's register schema floor is `min(3)`; legacy floor was 2). Regexp stays `[A-Za-z0-9_-]`.
- Never use `vi.mock()`/`vi.spyOn()` in new tests — use `Alepha.create().with({provide, use})` substitution.
- No `private` keyword in classes touching Alepha services — use `protected` (Alepha convention).
- All Alepha CLI invocations from an app dir: `npx alepha <cmd>` (alepha is a workspace dep, bin resolves).
- Commit after every green task. Conventional commits, French or English messages both fine (repo uses English).
- Run `npm run check:runtime` before each commit that touches `packages/*` (it skips creator map validation; full `npm run check` at the end of tranche 1).

## Verified recon findings the executor must know

1. **No co-hosting of the legacy WS on workerd.** Alepha's generated `main.cloudflare.js` routes upgrades only for paths derived from `$websocket` primitives, and `$route` cannot return a raw `Response`. This is WHY tranche 1 is a parallel run (`dev` vs `dev:legacy`) and the client stays on the legacy API until the realtime tranche.
2. **Extra Durable Objects in the generated wrangler are possible but fragile** (`build.cloudflare.config` spread + exporting the class from the server entry; migration tag `v1` collides with Alepha's). Not needed in tranches 0-1; recorded for the realtime tranche.
3. **`$action` auto-prefixes `/api`** — write `path: "/maps"`, get `/api/maps`. Method via `method: "PUT" | "DELETE"`.
4. **Error contract**: Alepha's `errorSchema` is `{error, status, message, details?}` — put the machine code in `error` via `new HttpError({status, error, message})`. Legacy client reads `{error}` already.
5. **`repo.transaction()` throws on D1** — always prefer the `$transactional()` middleware.
6. **Migrations are NOT generated in this tranche** — dev uses SQLite auto-sync (`DrizzleKitProvider.synchronize()`); the baseline is created at tranche 4 (`alepha db migrations create`), after the schema has settled through the realtime tranche.
7. **`alepha db`/`alepha dev` boot your server entry** (`ALEPHA_CLI_IMPORT=true`) — keep `apps/main/src/main.ts` side-effect-light.
